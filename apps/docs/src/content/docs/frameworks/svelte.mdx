`@lunora/svelte` is the Svelte adapter, an idiomatic layer over
[`@lunora/client`](/docs/packages/client) that re-expresses the live contract as
runes-native handles. A live query is an object whose `current` re-runs every
reader on each server delta; an optimistic mutation is a handle of reactive
properties plus an awaitable `mutate`. Reactivity is
[`createSubscriber`](https://svelte.dev/docs/svelte/svelte-reactivity#createSubscriber),
so the package stays plain `.ts` — no `.svelte`/`.svelte.ts` compiler step —
while every handle is tracked by `$derived`, `$effect`, and template reads.

This page is the task-oriented guide; for the full reference see
[`@lunora/svelte`](/docs/packages/svelte).

<Callout type="warn">
    **Preview.** The Svelte adapter exposes the same hydrate-then-subscribe handoff as React, but it is **preview** maturity: not yet proven end-to-end against
    a running app. See [Bring your framework](/docs/frameworks/bring-your-framework).
</Callout>

## Provide the client

There is no provider component. Publish the client on Svelte context with
`setLunoraClient(client)` once, high in the tree (your root `+layout.svelte` or
`App.svelte`), during component init. `query` / `mutation` / `hydratePreloaded`
resolve it for you; call `getLunoraClient()` only if you need it directly.

```svelte title="src/routes/+layout.svelte"
<script lang="ts">
    import type { Snippet } from "svelte";

    import { LunoraClient } from "lunorash/client";
    import { setLunoraClient } from "@lunora/svelte";

    let { children }: { children: Snippet } = $props();

    setLunoraClient(new LunoraClient({ url: import.meta.env.VITE_LUNORA_URL }));
</script>

{@render children()}
```

## Live queries

`query(fn, args)` opens a live query; read `handle.current`. The subscription
attaches on the first tracked read (a template, a `$derived`, an `$effect`) and
tears down once every effect that read it is destroyed — so an unread handle
opens no socket, and a server render opens nothing. `current` holds `undefined`
until the first response.

```svelte
<script lang="ts">
    import { query } from "@lunora/svelte";

    import { api } from "$lib/_generated/api";

    const messages = query(api.messages.list, { channelId: "general" });
</script>

<ul>
    {#each messages.current ?? [] as m (m._id)}
        <li>{m.text}</li>
    {/each}
</ul>
```

Read reactive members **off the handle**. `const { current } = query(...)`
copies the value once and it never updates. For args that change, build the
handle inside a `$derived.by` — each change constructs a fresh handle and the
previous subscription is released:

```svelte
<script lang="ts">
    import { query } from "@lunora/svelte";

    import { api } from "$lib/_generated/api";

    let channelId = $state("general");

    const messages = $derived.by(() => query(api.messages.list, { channelId }));
</script>

{#each messages.current ?? [] as m (m._id)}<li>{m.text}</li>{/each}
```

`query` is overloaded: pass `client` explicitly as the first argument, or omit
it to use the ambient client. `options` accepts `{ shardKey }` (for
`.shardBy(...)`-partitioned functions) and `{ onError }`.

## Mutations

`mutation(fn)` creates an optimistic `MutationHandle`:
`{ data, error, pending, mutate, reset }`. Read `handle.pending` to disable a
button; it is ref-counted across overlapping calls. You pass optimistic updates
**per call**.

```svelte
<script lang="ts">
    import { mutation } from "@lunora/svelte";

    import { api } from "$lib/_generated/api";

    const message = mutation(api.messages.send);

    const send = () =>
        message.mutate(
            { channelId: "general", text: "hi" },
            {
                optimisticUpdate: (store) => {
                    const current = store.getQuery(api.messages.list, { channelId: "general" }) ?? [];
                    store.setQuery(api.messages.list, { channelId: "general" }, [...current, { _id: "tmp", text: "hi" }]);
                },
            },
        );
</script>

<button disabled={message.pending} onclick={send}>Send</button>
{#if message.error}<p>{message.error.message}</p>{/if}
```

## Reactive loaders

Run the query on the server with the socket-free `@lunora/svelte/server` entry in
a SvelteKit `+page.ts` / `+layout.ts` `load`, return the serializable `Preloaded`
token, and `hydratePreloaded` seeds `current` **synchronously**. The first read
returns the server value with no loading flash, then the live subscription
attaches on the first tracked read in the browser.

```ts title="src/routes/posts/+page.ts"
import { createServerClient, preloadQuery } from "@lunora/svelte/server";

import { api } from "$lib/_generated/api";

export async function load({ fetch }) {
    // Forward SvelteKit's fetch so the session cookie rides along.
    const client = createServerClient({ url: import.meta.env.VITE_LUNORA_URL, fetch });
    const preloaded = await preloadQuery(client, api.posts.list, {});

    return { preloaded };
}
```

```svelte title="src/routes/posts/+page.svelte"
<script lang="ts">
    import { hydratePreloaded } from "@lunora/svelte";

    let { data } = $props();

    const posts = $derived(hydratePreloaded(data.preloaded));
</script>

<ul>
    {#each posts.current as p (p._id)}
        <li>{p.title}</li>
    {/each}
</ul>
```

See [Reactive loaders](/docs/frameworks/reactive-loaders) for the full handoff.

## One worker, one deploy

SvelteKit owns its Cloudflare build via `@sveltejs/adapter-cloudflare`
(class-B, "own CF adapter, hook-injection"), so Lunora **injects** its realtime
plane into the worker SvelteKit emits, via `buildFrameworkWorker` on the
generated app (`withFrameworkWorker` from `@lunora/runtime` under the hood):
reserved `/_lunora/*` endpoints hit Lunora, everything else delegates to
SvelteKit. One worker, one deploy.

```ts title="src/worker.ts"
import svelteKitWorker from "../.svelte-kit/cloudflare/_worker.js"; // adapter output

import { defineApp } from "../lunora/_generated/app";

const app = defineApp<Env>()
    .shard((env) => env.SHARD)
    .buildFrameworkWorker(svelteKitWorker);

export const ShardDO = app.ShardDO;
export default app;
```

See [Bring your framework](/docs/frameworks/bring-your-framework) for the full
composition contract, and [Deploy your framework](/docs/frameworks/deploy).
